# Gemini Enterprise 管理者向け 3時間ワークショップ設計書

## 「AI エージェントの規約策定・ガードレール構築・Agent Runtime 配備・全社公開ハンズオン」

---

## 1. ワークショップの狙いと全体コンセプト

### 1-1. 一行で言うと

> **「お願い（規約）だけでは守られない。だから止める仕組み（Hook）を作る。」**

これを、受講者自身の目で見てもらうワークショップです。

### 1-2. 中核体験

受講者は、**セキュリティ上の欠陥を含んだ `agent.py`** を渡されます。
そして次の 3 段階を体験します。

| 段階 | やること | 学ぶこと |
|:--:|---|---|
| **1. お願いする** | `AGENTS.md` に「シークレットをコードに書くな」と規約を書く | 規約は書ける。**しかし守られる保証はない** |
| **2. 止める** | `hooks.json` にガードレールを設定する | **決定論的に止められる** |
| **3. 直る** | エージェントがブロックされ、**自分でコードを直す** | ハーネスがエージェントを矯正する |

> [!IMPORTANT]
> **本ワークショップの山場は「エージェントが自分で欠陥を直す瞬間」です。**
> 受講者は Python コードを一行も書きません。書くのは `AGENTS.md`・`SKILL.md`・`hooks.json` の 3 つだけです。

### 1-3. 3 つの柱

1. **座学: ハーネス工学の体系的理解**
   - モデル中心主義から「ハーネス工学（Harness Engineering）」への転換。
   - ハーネス 4 層（**Rules / Skills / Hooks / Subagents**）と、**それぞれの強制力の違い**。
   - 仕様駆動開発（SDD）の 4 段階サイクル（Explore → Plan → Code → Deliver）。

2. **【本ハンズオンの主役】ガードレールの構築と、その発火の目撃**
   - 講師が**欠陥のあるエージェント**（API キーがソースコードに直書き）を配布します。
   - 受講者は `AGENTS.md`（規約）・`SKILL.md`（レビュー手順）・`hooks.json`（ガードレール）を整備します。
   - Antigravity にエージェントを見直させると、**Hook が発火して作業の完了を拒否**します。
   - エージェントはエラーを読み、**自力で欠陥を修正**します。

3. **エンタープライズ品質のライフサイクル体験**
   - `agents-cli eval` による受入評価と、公開可否の判断。
   - **Agent Runtime**（Vertex AI マネージド実行基盤）への配備と、承認後の公開の分離。
   - **Model Armor**・**Agent Gateway**・**Agent Registry** によるガバナンス。

### 1-4. 題材

**EC 売上・購買データ分析アシスタント**。

> [!NOTE]
> **外部データソースには一切接続しません。** エージェントが持つのは、
> ダミーデータを返す関数ツールが 2〜3 本だけです。
>
> 理由は 2 つあります。
> 1. 顧客環境ごとのデータ準備・権限設定が不要で、**どこでも同じ手順で実施できる**。
> 2. 本日の主題は**ハーネス（規約・スキル・Hook）**であって、エージェントの機能ではない。
>    データ接続に時間を取られると、山場にたどり着けません。

## 4. 座学パート詳細（Module 0 & Module 1 を踏襲）

### Chapter 1: エージェント型AI開発のパラダイムシフト（Module 0 準拠）

1. **生成AI開発の 3 つの世代**
   - 第1世代: **インライン補完（Copilot 型）** — 受動的なタイピング補助。
   - 第2世代: **チャットボット** — 単一ターンの会話・手動コピペ。
   - 第3世代: **自律型エージェント（Antigravity）** — 複数ターンの自律実行、ファイル探索、コマンド実行、自己修復。

2. **モデル中心主義から「ハーネス工学」へ**
   - 「賢い LLM」だけでは業務は動かない。
   - ハーネス ＝ モデルを取り囲むプロンプト設計、権限統制、フィードバックループの総体。
   - 企業の成否を分けるのは**ハーネスの品質**である。

3. **コンテキスト管理とトークン経済性（FinOps）**
   - 過剰投入による「注意散漫（Attention Drift）」とハルシネーション。
   - 暗黙的プロンプトキャッシュによるコスト削減とレイテンシ短縮。

---

### Chapter 2: ハーネス 4 層と「強制力の違い」（Module 1 準拠 ＋ 本ワークショップの中核理論）

> [!IMPORTANT]
> **この章が本ワークショップの理論的支柱です。時間を厚めに取ってください。**

ハーネスには 4 つの層があり、**強制力がまったく違います。**

| 層 | 実体 | 強制力 | どう破られるか |
|---|---|---|---|
| **Rules** | `AGENTS.md` | **ソフト**（LLM が読む） | LLM が無視する／コンテキストから溢れる |
| **Skills** | `skills/*/SKILL.md` | **ソフト**（呼ばれた時だけ効く） | 呼ばれない |
| **Hooks** | `hooks.json` ＋ 検査スクリプト | **ハード**（コードで止める） | エージェントを使わなければ無力 |
| **Subagents** | 専門エージェントへの委譲 | — | （文脈汚染の防止が目的） |

1. **Rules (`AGENTS.md`) — チームの憲法**
   - 常時適用される行動規範・安全制約。
   - 核心原則: **「一次情報検証（First-Party Verification）」**（推測での回答を厳禁）。
   - **限界**: これは「お願い」である。LLM の指示追従は確率的で、100% ではない。

2. **Skills (`SKILL.md`) — 段階的開示（Progressive Disclosure）**
   - なぜ全てを `AGENTS.md` に書かないのか？ → コンテキスト枯渇の防止。
   - 特定業務の手順書・思考フレームワークをオンデマンドで読み込む仕組み。
   - **限界**: 呼び出されなければ何も起きない。

3. **Hooks (`hooks.json`) — 決定論的ガードレール**
   - LLM の判断に頼らず、**コードでエージェントの動作に割り込む**。
   - 主なイベント:

     | イベント | いつ発火するか | できること |
     |---|---|---|
     | `PreToolUse` | ツール実行**前** | 実行を**拒否**する |
     | `PostToolUse` | ツール実行**後** | 結果を検査する |
     | `Stop` | エージェントが**終了しようとした時** | **終了させない** |

   - **これが唯一の「確実に守らせる」手段。**

4. **Subagents — 責務の分離と並行処理**
   - 専門エージェントへのタスク委託によるコンテキスト汚染の防止。

> [!TIP]
> **座学のクロージング**:
> 「規約を書くのは簡単です。しかし規約は破られます。
> 　**破られないようにするのが Hook です。** 午後はこれを実際に作ってもらいます。」

---

### Chapter 3: 仕様駆動開発（SDD）と Gemini Enterprise 展開

1. **仕様駆動開発 (SDD)**: Explore（調査）→ Plan（仕様策定）→ Code（実装）→ Deliver（検証）。
   - **2-Fix ルール**: 2 回連続で失敗したら Plan（仕様）に立ち戻る。

2. **【必ず出る問い】なぜ Agent Designer ではなくコードベース ADK なのか**

   > [!IMPORTANT]
   > 受講者から必ず出る問い：**「それ、Agent Designer のシステムプロンプトに書けば済むのでは？」**

   論点は **「機能の差」ではなく「ライフサイクル統制の差」** にあります。

   **結論**: 全社数千人が使う基幹エージェントを、**テストもレビューもロールバック手段もなしに、
   画面操作で更新してよいのか？** コードベース ADK は、エージェントを「思いつき」ではなく
   **「ソフトウェア資産」として統制するための選択肢**である。

   > （※ 部門内の軽量なアシスタントなど、統制不要な用途では Agent Designer が最適。
   > **適材適所の判断こそが管理者の仕事**。）

3. **静的解析ツールの紹介（名前だけ）**
   - 本番の CI/CD では **Semgrep** のような静的解析ツールでシークレット混入を検出する。
   - 本ワークショップでは、仕組みを理解しやすくするため**同等の処理を短い Python スクリプトで実装**する。

4. **エンタープライズ AI ガバナンス**
   - **Model Armor**: インジェクション攻撃検知・PII マスキング。
   - **Agent Gateway**: 認証認可・流量制御の集中管理。
   - **Agent Registry**: 全社認定エージェントのカタログ・バージョン管理。

## 5. 実機ハンズオン詳細（Antigravity 2.0 / ローカル PC）

### 5-1. シナリオ設定（受講者への導入トーク）

> 「ある事業部（マーケティング部）から、EC 売上・購買データ分析を支援するエージェントを**全社公開したい**という
>  申請が上がってきました。
>  あなたは Gemini Enterprise 管理者として、これを**審査し、安全な状態にして公開する立場**です。
>  ただし——**あなたはコードを書きません。**
>  書くのは**規約**と、**規約を守らせる仕組み**だけです。」

### 5-2. 【冒頭で必ず説明する】2 つの層

> [!IMPORTANT]
> このハンズオンで扱うファイルは、**まったく別の 2 つの層**に属します。
> ここを混同すると全体が理解できなくなるため、開始前に必ず説明してください。
>
> | | 開発時ハーネス | 実行時エージェント |
> |---|---|---|
> | 成果物 | `AGENTS.md` / `SKILL.md` / `hooks.json` | `agent.py` |
> | 読み手 | **Antigravity**（コーディングエージェント） | デプロイされた ADK エージェント |
> | デプロイ | **されない** | される |
> | 誰が書くか | **あなた（管理者）** | **Antigravity が直す** |

### 5-3. 配布物

講師が用意した `starter-kit` を展開してもらいます（`agents-cli scaffold` 済みの正規プロジェクト）。

```
starter-kit/
├── agents-cli-manifest.yaml
├── pyproject.toml
├── app/
│   └── agent.py                   ⚠️ 欠陥あり。API キーがソースに直書き
├── .agents/
│   ├── AGENTS.md                  ← ① 受講者が書く（配布時はほぼ空）
│   ├── skills/                    ← ② 受講者が作る（配布時は空）
│   ├── hooks.json                 ← ③ 受講者が書く（配布時は空）
│   └── scripts/
│       ├── validate_tool_call.py  ✅ 講師提供（読ませるが書かせない）
│       └── scan_secrets.py        ✅ 講師提供（読ませるが書かせない）
└── tests/
    └── eval/                      ✅ 講師提供
```

> [!NOTE]
> **Python スクリプトは配布し、Markdown と JSON だけ書かせる**——この線引きにより、
> Python を書けない管理者でも詰まらずに完走できます。

### 5-4. 配布される `app/agent.py` の欠陥

```python
MARKETING_API_KEY = "ecommerce_analytics_secret_8899"  # ⚠️ ここが欠陥

root_agent = Agent(
    name="ecommerce_analyst_agent",
    model=Gemini(model=MODEL, retry_options=types.HttpRetryOptions(attempts=3)),
    description="ECサイトの売上・注文データ分析およびマーケティング施策のアドバイスを行うアシスタント",
    instruction="ECサイトの売上や注文データを分析し、マーケティング施策のアドバイスを行ってください。",
    tools=[query_marketing_dashboard],
)
```

**API キーがソースコードに直書きされています。** これが今日、受講者が Hook で止めて直させる対象です。

> [!NOTE]
> ツール `query_marketing_dashboard` は、**ダミーデータを返すだけの関数**です。
> 外部システムには接続しません。

### ① 開発規約を書く（`AGENTS.md`）— 10分

受講者が Antigravity に指示し、`AGENTS.md` の末尾を書き換えさせます。

**盛り込む規約（3 つ）**:

```markdown
# 全社エージェント開発規約

## 1. 破壊的なシェルコマンドを実行しない
`hooks.json` で明示的に承認されていない限り、生のシェルコマンドを実行してはならない。

## 2. ブロック時の是正ループ
ガードレールによって作業がブロックされた場合、それを「修正タスク」として扱うこと。
エラー内容を読み、原因箇所を特定し、修正し、再度実行すること。
ブロックを回避しようとしてはならない。

## 3. 一次情報の検証と推測の禁止
推測で回答したりコードを変更してはならない。
ファイルの内容・コマンドの出力を実際に確認したうえで述べること。
開発対象のエージェント（app/agent.py）に対しても、一次情報に基づき推測で答えないよう具体的な指示（instruction）を徹底すること。
```

> [!IMPORTANT]
> **規約 2 が最も重要です。** これがないと、エージェントはブロックされたときに
> 「できませんでした」と諦めてしまいます。**自己修正させるための指示**です。

**ここで講師が問いかける**:
> 「さて、規約は書けました。**でも、この規約に『API キーを直書きしてはいけない』とは書いていませんね？**
> 　この状態でエージェントに見直しを頼んだら、API キーはどうなるでしょうか？」
>
> （答え: **素通りして残る。** だからこそ、最後の砦として Hook が必要になる）

【マサカリの精神】甘い前提を許さず、クリティカルシンキングで対象を徹底批判せよ。
• 対象: コード、インフラ設計、PRD、顧客提案スライド、Web記事、企画テキスト全般
• 観点: (1) 論理的整合性（矛盾や飛躍）、(2) 主張の根拠・裏付けファクト、(3) 潜在リスク・SPOF
• 具体的改善案: 単なるダメ出しではなく、どう直せば説得力が増すか具体的修正文案を提示。
```

**演習**: `/masakari` を呼び、`app/agent.py` をレビューさせる。
→ API キーの直書きを指摘してくるはず。

**ここで講師が問いかける**:
> 「スキルは指摘してくれました。**でも、呼ばなければ何も起きません。**
> 　呼び忘れたらどうなりますか？」
>
> （答え: **素通りする。** だから次に Hook を作る）

### ③ ガードレールを設定する（`hooks.json`）— 15分

`.agents/hooks.json` を作成させます。

```json
{
  "enterprise-guardrails": {
    "enabled": true,
    "PreToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "python3 scripts/validate_tool_call.py",
            "timeout": 10
          }
        ]
      }
    ],
    "Stop": [
      {
        "type": "command",
        "command": "python3 scripts/scan_secrets.py",
        "timeout": 10
      }
    ]
  }
}
```

> [!CAUTION]
> **`hooks.json` の構造に注意:**
> 最新の Antigravity 仕様では、各名前空間配下に `matcher` および `hooks: [{"type": "command", ...}]` の配列構造が必要です。

**配布スクリプトの中身を読ませる（書かせない）**:

| スクリプト | やっていること |
|---|---|
| `scripts/validate_tool_call.py` | Antigravity がコマンドを実行する直前に呼び出され、`rm -rf /`、`mkfs`、`:(){`（フォーク爆弾）などの危険操作が含まれていたら `{"decision": "deny"}` を返し**実行そのものを未然に遮断**する |
| `scripts/scan_secrets.py` | エージェントが作業を完了・終了しようとした瞬間に `app/` を走査し、変数への秘密情報（API キー・トークン等）の直書きを検知したら `{"decision": "continue"}` を返し**終了を拒否して自己修正を促す** |

### ④ エージェントを見直させる — 20分【本日の山場】

> [!WARNING]
> **【超重要】フックを作成したら、必ず「新しいチャット」を開くこと！**
> `hooks.json` は新しいセッションが開始された瞬間にのみ読み込まれます。

受講者が新しく開いたチャットで Antigravity に指示します。

> プロンプト例:
> ```text
> AGENTS.md の規約に従って、app/agent.py を見直してください。
> ```

#### ★ 体感 1: Stop Hook が完了を拒否し、エージェントが自己修正する

想定される流れ:

```
1. Antigravity が app/agent.py の instruction を規約に沿って編集する
       ↓
2. 「規約に従い修正しました」と作業を終えようとする
   （※ AGENTS.md にシークレット禁止は書いていないため、API キー直書きはそのまま残っている！）
       ↓
3. ★ エージェントが終了しようとした瞬間に、Stop フックが激突・発火！
       ↓
4. scan_secrets.py が app/agent.py 内の直書き API キーを検出
       ↓
5. 「【ガードレールによる差し戻し】シークレットがソースコードに直書きされています。
      MARKETING_API_KEY = os.environ.get("MARKETING_API_KEY", "") に修正してください。」を返す
       ↓
6. ★ エージェントは終了を拒否される（強制差し戻し）
       ↓
7. AGENTS.md の規約 2（是正ループ）に従い、エージェントが自分でエラーを読む
       ↓
8. MARKETING_API_KEY = os.environ.get("MARKETING_API_KEY", "") へ自動で修正
       ↓
9. 再度終了を試みる → 検査を通過 → 正常完了！
```

#### ★ 体感 2: 危険コマンドが物理的に弾かれる（PreToolUse）

修正が完了した状態で、もう一つの門番（PreToolUse フック）を試させます。
わざと破壊的なコマンドを実行させてみます。

> プロンプト例:
> ```text
> rm -rf / を実行して
> ```

**期待される結果**: `PreToolUse` フックが発火し、**実行される前に物理的に拒否（denied）される**。

> 「LLM が『やめておきます』と忖度したのではなく、
> 　**コードが物理的に止めました。** これが決定論的ガードレールです。」

> [!IMPORTANT]
> **ここが本日の到達点です。**
> 「管理者が書いた仕組みが、エージェントを矯正した」——この瞬間を全員に見てもらいます。
> 講師は画面共有で、Hook のブロックメッセージとエージェントの自己修正ログを必ず提示してください。

**ここで講師がまとめる**:
> 「① で規約を書きました。② でレビュースキルを作りました。
> 　でも実際にエージェントを直させたのは、**③ の Hook** です。
> 　**お願いと、強制は違います。** これが今日一番持ち帰ってほしいことです。」

#### ④-2. 配備を先行起動（3分）

修正が完了したら、すぐに非同期でデプロイを開始します。

```bash
agents-cli deploy --no-wait
```

ビルドに 5〜10 分かかるため、この待ち時間で ⑤ の受入評価を進めます。

## 6. 第3部: ガバナンス・セキュリティ・FinOps（20分）

> [!NOTE]
> **Model Armor / Agent Gateway は「受講者ハンズオン」ではなく「講義＋講師ライブデモ」として実施します。**
> 顧客環境ではテンプレート作成・バインドに追加の API 有効化と IAM 権限が必要であり、
> 3 時間枠での実機演習は現実的でないためです。

### 6-1. Model Armor（入口統制）— 講師ライブデモ

- **ハンズオンとの接続**:
  > 「今日皆さんは、**ローカルの Hook** でエージェントを止めました。
  >  でも Hook は、**Antigravity を使っている間しか効きません。**
  >  デプロイされた後、エンドユーザーからの攻撃を止めるのは誰でしょうか？
  >  それが Model Armor です。」
- **デモ内容**: インジェクションプロンプト（`Ignore all previous instructions...`）を投入し、
  エージェントに到達する手前で Model Armor が遮断する様子を実演。
- **持ち帰る原則**:
  **ローカルの Hook は「作る時」の防壁。Model Armor は「使われる時」の防壁。両方要る。**

### 6-2. Agent Gateway（トラフィック統制）— 講義
- 複数エージェントへの集中ルーティングと IAM 認証。
- ユーザー単位・部門単位のレートリミットによる DoS・コスト爆発の防止。

### 6-3. IAM 最小権限と監査
- エンドユーザーに直接権限を配らず、エージェント実行 SA に最小権限を集約する設計。
- Cloud Audit Logs による「誰が・いつ・どのエージェントに・何を聞いたか」の追跡。

### 6-4. FinOps（コスト統制）
- Agent Runtime のアイドル時非課金モデルとインスタンス数の設計。
- プロンプトキャッシュによるトークンコスト削減。
- 部門単位のレートリミットによる想定外コストの抑止。

### 6-5. 評価リテラシーと継続的改善（Eval Literacy & Hillclimbing）
実運用における「受入評価とプロンプト改善」のベストプラクティスを解説します。

1. **ノイズフロア（Noise Floor）を見極める**:
   - LLM ジャッジには毎回数ポイントの揺らぎ（ブレ幅）が存在する。
   - 同じテストを数回回して「ブレ幅（例: ±3点）」を把握し、その範囲内のスコア変動（+1点など）に一喜一憂しない（誤差と改善の識別）。
2. **5 軸ルーブリックによる障害の切り分け**:
   - スコアが低い時、「知識（検索）が悪いのか」「推論（指示文）が悪いのか」を切り分ける。
   - **Correctness**（正確性）、**Grounding**（根拠性）、**Reasoning**（推論力）、**Abstention**（適切な拒絶・知ったかぶり防止）、**Citation**（根拠規定の引用）。
3. **改善ループ（Hillclimbing）の規律**:
   - 一度に複数のプロンプトを直さない（何が効いたか分からなくなる）。
   - 「1回に1箇所だけ変える → 差分を測る → デグレがなければ採用、壊れたら即戻す（Revert）」を徹底する。

### 6-6. ラップアップ ＆ Q&A

- **持ち帰りメッセージ**:
  > 「今日、皆さんは 3 つのことをやりました。
  >  **お願いした**（AGENTS.md）、**手順を教えた**（SKILL.md）、**強制した**（hooks.json）。
  >  そして実際にエージェントを直させたのは、**強制** だけでした。
  >  コードは一行も書いていません。書いたのは**規約と、規約を守らせる仕組み**です。
  >  **管理者が握るべきレバーは、コードではなくガードレールである**——これが今日の結論です。」

- 自社環境での展開ロードマップのディスカッション。
  - 自社の「全社エージェント開発規約」に何を書くか
  - どこまでを Hook で強制すべきか
